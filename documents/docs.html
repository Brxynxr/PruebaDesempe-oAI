2. Decisiones de Diseño y Arquitectura

En este capítulo se desglosan las decisiones de ingeniería fundamentales tomadas para garantizar escalabilidad, seguridad, baja latencia y mantenibilidad del sistema.

Backend: FastAPI
Elegido

Por qué se eligió: Ecosistema de tipado estricto con Pydantic v2, rendimiento asíncrono ASGI nativo y compatibilidad perfecta con ChromaDB y Groq.

Alternativas descartadas: Node.js/Express (menor soporte nativo para librerías de vectorización en Python), Flask (síncrono por defecto y sin validación OpenAPI nativa).

Inferencia: Groq Cloud API
Elegido

Por qué se eligió: Inferencia de ultra baja latencia (<300ms TTFT) gracias a chips LPU, compatibilidad OpenAI y temperatura 0.2 altamente determinista.

Alternativas descartadas: OpenAI Directo (mayor latencia y costo por token), Modelos Locales (exigen GPUs pesadas inviables para contenedores ligeros).

Vector Store: ChromaDB
Elegido

Por qué se eligió: Base vectorial embebida y persistente en disco local (./chroma_data), sin dependencias SaaS externas y con búsqueda por similitud coseno.

Alternativas descartadas: Pinecone (costos recurrentes y latencia SaaS), FAISS (requiere programación manual de persistencia y metadatos).

Router: n8n Engine
Elegido

Por qué se eligió: Desacoplamiento total. El backend aloja el core de RAG y seguridad; n8n actúa como adaptador visual para canales externos (Telegram, Meta WhatsApp, CRM).

Beneficio clave: Conectar nuevos canales de mensajería sin recompilar ni alterar el código Python.

Diagrama de Arquitectura Global de Componentes
1. Entrada Web SPA / n8n React 18 con X-API-Key y soporte bilingüe
2. Seguridad FastAPI Core Rate Limit + Anti-Injection + IP Sanitizer
3. Recuperación ChromaDB + TTL Búsqueda semántica coseno y memoria caché
4. Inferencia Groq LPU (T=0.2) Síntesis factual sin alucinaciones
5. Salida Respuesta / Lead Despacho SMTP + WhatsApp prellenado

3. Glosario y Conceptos Técnicos

RAG

Retrieval-Augmented Generation: Patrón donde el LLM solo responde basándose en fragmentos recuperados en tiempo real desde la base documental.

Chunking (400/50)

División de documentos en bloques de 400 caracteres con 50 de solapamiento (overlap) para mantener coherencia contextual.

Caché TTL (3600s)

Memoria en tiempo real que responde preguntas frecuentes en <10ms con 0 costo de tokens mediante clave normalizada.

Prompt Injection

Intento de engañar al LLM. Se neutraliza mediante normalización Unicode NFKD y traducción de leetspeak (!gn0r3).

Rate Limiting

Limitador de 10 req/min por IP real con validación ipaddress contra falsificaciones de cabeceras de proxy.

Temperatura 0.2

Configuración del LLM para forzar respuestas altamente deterministas y apegadas estrictamente a los hechos oficiales.

4.1 Recorrido Backend (Código Real)

1. Rate Limiting y Anti-IP Spoofing (app/core/security.py)

Valida que las IPs recibidas desde cabeceras como X-Forwarded-For o X-Real-IP tengan una estructura de red legítima antes de usarlas como clave en SlowAPI.

backend/app/core/security.py 
import ipaddress
from fastapi import Security, HTTPException, status, Request
from fastapi.security.api_key import APIKeyHeader
from slowapi import Limiter
from app.core.config import settings

api_key_header = APIKeyHeader(name="X-API-Key", auto_error=False)

def _get_real_client_ip(request: Request) -> str:
    """Extract real client IP safely with ipaddress validation to prevent spoofing."""
    real_ip = request.headers.get("X-Real-IP")
    if real_ip:
        clean_ip = real_ip.strip()
        try:
            ipaddress.ip_address(clean_ip)
            return clean_ip
        except ValueError:
            pass

    forwarded_for = request.headers.get("X-Forwarded-For")
    if forwarded_for:
        raw_ip = forwarded_for.split(",")[0].strip()
        try:
            ipaddress.ip_address(raw_ip)
            return raw_ip
        except ValueError:
            pass

    return request.client.host if request.client else "127.0.0.1"

limiter = Limiter(key_func=_get_real_client_ip, default_limits=[settings.RATE_LIMIT_PER_MINUTE])
¿Por qué está escrito así y qué pasaría si no estuviera?
Si no se validara con ipaddress.ip_address(), un atacante podría enviar una cabecera como X-Forwarded-For: fake-ip-123 en cada solicitud, saltándose por completo el límite de tasa y consumiendo la cuota de la API de Groq.

2. Guardrails Anti-Prompt Injection (app/core/guardrails.py)

backend/app/core/guardrails.py 
import re
import unicodedata
from fastapi import HTTPException, status

LEET_MAP = {
    '0': 'o', '1': 'i', '!': 'i', '|': 'i', '3': 'e',
    '4': 'a', '@': 'a', '5': 's', '$': 's', '7': 't',
}

def _normalize_text(text: str) -> str:
    """Normalize unicode NFKD, translate leetspeak and collapse whitespace."""
    if not text:
        return ""
    nfkd = unicodedata.normalize("NFKD", text)
    stripped = "".join(c for c in nfkd if not unicodedata.combining(c)).lower()
    leet_translated = "".join(LEET_MAP.get(c, c) for c in stripped)
    cleaned = re.sub(r"[`*_\-#\/\\\[\]\(\)\{\}:;\"']", " ", leet_translated)
    return re.sub(r"\s+", " ", cleaned).strip()

def validate_prompt_injection(message: str) -> None:
    normalized = _normalize_text(message)
    for pattern in PROMPT_INJECTION_PATTERNS:
        if re.search(pattern, normalized):
            raise HTTPException(
                status_code=status.HTTP_400_BAD_REQUEST,
                detail="Request rejected: potential prompt manipulation detected."
            )

def generate_response(self, user_message: str, session_id: str = "default", language: str = "es", history: Optional[List[Dict[str, str]]] = None) -> ChatResponse:
    lang_code = "en" if language.lower().startswith("en") else "es"
    
    # 1. Chequeo de Caché TTL
    cache_key = f"{lang_code}:{user_message}"
    cached_resp = response_cache.get(cache_key)
    if cached_resp:
        metrics_service.record_query(is_cached=True, is_escalated=cached_resp.is_escalated, tokens=0)
        return cached_resp

    # 2. Búsqueda contextual enriquecida con turnos previos
    search_query = user_message
    if history and len(user_message.split()) < 7:
        last_turn_text = " ".join([h.get("text", "") or h.get("content", "") for h in history[-2:]])
        search_query = f"{user_message} {last_turn_text}".strip()

    search_results = self.vector_store.search(query=search_query, top_k=6)
    
    # 3. Construcción del Prompt con System, Few-Shots e Historial
    messages = build_messages(user_question=user_message, context_chunks=search_results, language=lang_code, history=history)

    # 4. Inferencia en Groq LPU (temperatura 0.2)
    chat_completion = self.client.chat.completions.create(
        messages=messages,
        model="openai/gpt-oss-120b",
        temperature=0.2,
        max_tokens=500
    )
    raw_answer = chat_completion.choices[0].message.content
    is_escalated = _check_strict_escalation(user_message, raw_answer)
    whatsapp_link = _build_whatsapp_link(user_message, language=lang_code) if is_escalated else None

    final_response = ChatResponse(
        response=raw_answer,
        is_escalated=is_escalated,
        whatsapp_link=whatsapp_link,
        session_id=session_id
    )
    if not is_escalated:
        response_cache.set(cache_key, final_response)
    metrics_service.record_query(is_cached=False, is_escalated=is_escalated, tokens=350)
    return final_response

4.2 Recorrido Frontend SPA (React / Vite)

Gestión de Escalamiento Sí / No en FloatingChat.jsx

Implementa la confirmación interactiva antes de abrir el formulario de leads, mejorando drásticamente la experiencia de usuario.

frontend/src/components/FloatingChat.jsx 
const handleEscalationDecision = (msgIndex, accepted) => {
  setMessages((prev) => {
    const updated = [...prev];
    if (updated[msgIndex]) {
      updated[msgIndex] = {
        ...updated[msgIndex],
        escalationChoice: accepted ? 'accepted' : 'declined'
      };
    }
    if (!accepted) {
      updated.push({
        sender: 'bot',
        text: t('chatAdvisorDeclined'),
        isEscalated: false,
        isClosed: false,
        escalationChoice: null
      });
    }
    return updated;
  });
};

6. Arquitectura de Ciberseguridad (4 Capas)

Capa Mecanismo Técnico Implementación Limitación Conocida
1. Rate Limiting 10 req/min por IP con resolución segura de proxys. core/security.py IPs compartidas en redes NAT corporativas comparten cuota.
2. Anti-Injection Normalización Unicode NFKD + Leetspeak + Regex. core/guardrails.py Ataques semánticos indirectos muy sutiles requieren auditoría periódica.
3. API Key Auth Cabecera obligatoria X-API-Key. core/security.py En SPA pública la clave viaja en cliente; se complementa con CORS y Rate Limit.
4. Redacción PII & XSS Enmascaramiento de cédulas y escape HTML en correos. services/email_service.py Aplica a texto plano y formularios, no a archivos adjuntos no estructurados.
